# Zone Reward — заметки по дизайну (на будущее)

Выводы из разбора `notebooks/zone_reward_eval.ipynb` на реальных human-кругах (Magione, Porsche 911 RSR 2017). Фиксируем до того, как дойдёт до реального gym и обучения.

## Область применения — где это живёт

Zone reward — инструмент **Tuning Agent + диагностики**, не основной objective **Driving Agent**.

- Driving Agent (SAC, core-обучение) получает reward из физики трассы/машины напрямую: `+ скорость вдоль трассы - штраф за вылет - резкость inputs`. Human baseline тут не участвует вообще.
- Human baseline входит только как **критерий остановки файнтюна** ("готово, когда бьём человека") и как **эталон для Tuning Agent** при сравнении сетапов машины.
- Причина разделения: если baseline станет частью core-reward вождения, потолок навыка агента структурно привязывается к человеческому — а нам нужен предел машины, а не предел водителя.

## Ограничение самой разметки зон

Границы зон вычисляются по **моему** `g_lat`/`g_lon` (где я лично выхожу на ноль поперечной перегрузки и разгоняюсь). Значит подзонная разметка — это слепок конкретно моей техники прохождения, а не объективная структура трассы.

- Общее время круга остаётся честным (просто секунды на всей дистанции) для любой траектории.
- А вот подзонная диагностика ("где именно теряем время") перестаёт быть осмысленной для агента, который проходит трассу принципиально иначе (другие точки торможения/поворота/апекса) — она не запрещает такую траекторию, просто не видит её по кускам.
- Вывод: zone-breakdown — инструмент объяснения и тюнинга, не ограничение на форму траектории агента.

## Reward shaping: штраф — норма, награда — заслужена

Не выбираем между "жёстко" и "прощаем" вручную — используем зону нечувствительности вокруг человеческого baseline, откалиброванную по разбросу самого человека (`std_zone`), и НЕ делим на std (это разбавляет вес больших/шумных зон, где реально теряется больше всего секунд — агент находит лазейку вылизывать мелкие стабильные куски вместо большого рискованного).

```
reward_zone =
    (baseline - k·std) - agent_time      если edет agent_time < baseline - k·std   (реально обогнал — награда)
    0                                     если |agent_time - baseline| <= k·std    (в пределах шума человека — не судим)
    (baseline + k·std) - agent_time       если agent_time > baseline + k·std       (хуже человека — штраф)
```

Всё в сырых секундах (мс), без нормировки на дисперсию — так вес зоны в reward пропорционален её реальному вкладу в лаптайм.

Награда положительна и не ограничена сверху только когда агент статистически убедительно (не на шуме) обгоняет человека — не даём фармить позитив на удаче в шумной зоне.

## Baseline должен быть фиксирован, а не гоняться за агентом

Baseline (и веса `frozen_*.pth`) считаются **один раз** и не пересчитываются по ходу тренировки агента. Если делать сложность/порог зависимыми от текущего прогресса агента — это non-stationary reward / moving target: агент объективно улучшается, но не получает за это сигнала, потому что цель "убежала" вместе с ним. Ломает обучение критика (value-оценки постоянно устаревают).

`std_zone` в формуле выше — тоже фиксируется один раз по человеческим данным, не пересчитывается от агента.

## Сколько кругов нужно для baseline

Зависит от того, как считаем baseline:

- **min** (лучшее из виденного) — оценка экстремума, сходится медленно. Минимум из 5 кругов почти гарантированно хуже истинного предела человека и будет проваливаться глубже с каждым новым записанным кругом. Нужны десятки кругов на зону для честного "потолка".
- **медиана/процентиль** — сходится быстро (5-10 кругов достаточно), но это "типичный хороший круг", не рекордный.

На текущих 5 чистых кругах (`sane_laps` в ноутбуке) min ещё явно не вышел на плато — перед тем как доверять min-baseline, стоит проверить running-minimum по мере добавления кругов (растёт/падает или уже плато).

## Эмпирика с текущих 5 кругов (Magione, для справки)
