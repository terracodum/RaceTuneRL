# Конфиг Porsche 911 RSR 2017 для среды

## Где что лежит

RSR — наша машина, не пример апстрима, поэтому конфиг лежит в основном
репо: `racetune/ac_configs/cars/ks_porsche_911_rsr_2017/`, не в
`third_party/assetto_corsa_gym`. Сабмодуль — форк только ради кода
апстрима, не хранилище наших артефактов (см. `CLAUDE.md`). Существующие
примеры (`dallara_f317`, `bmw_z4_gt3`, `ks_mazda_miata` — ниже в
сравнительной таблице) не трогал и не переносил: они часть форка, были
там до этой задачи, используются только как референс для сравнения
методики.

`ac_configs_path` при использовании RSR+Magione нужно явно указывать на
`racetune/ac_configs` (параметр уже есть в апстриме, ничего не патчил —
подробности в `docs/reports/magione_track_files.md`).

## Как устроен per-car конфиг в env — сравнение существующих машин

Реально car-specific в `AssettoCorsaConfigs/cars/<car>/` (здесь и в
таблице ниже — путь **внутри сабмодуля**, `third_party/assetto_corsa_gym/assetto_corsa_gym/AssettoCorsaConfigs/cars/`,
это про референсные машины апстрима, не про RSR) только два файла:
`steer_map.csv`, `brake_map.csv`. Остальные "параметры машины", которые
собирает `structures.py` (`StaticInfo.collect_static_info`), в код env
(`ac_env.py`, `ac_client.py`) **не попадают вообще** — проверено grep'ом
по `AssettoCorsaEnv/*.py`, единственные потребители `static_info` —
`TrackLength`, `TrackFullName`, `CarName` (`ac_env.py:638,660-661`).

| Параметр | Что это | Откуда авторы брали | Используется в коде |
|---|---|---|---|
| `steer_map.csv` → `max_steer_deg`, `norm_steer_at_max` | Макс. угол поворота колёс (град.) и соответствующая нормализованная команда руля | **Измерено телеметрией**, не введено вручную — см. ниже | `ac_env.py:309-311,321` (масштаб action↔градусы, `controls_min/max_values`) |
| `brake_map.csv` (11 точек, x∈[-1,1]→y∈[0,1]) | Кривая отклика тормоза AC (команда → `brakeStatus`) | **Измерено телеметрией** (см. ниже) | `data_loader.py:41-42,48` — только для восстановления action из записанной телеметрии (`get_actions_from_state`), в live-агенте не используется |
| `CAR_MASS`, `CAR_DIM_X/Y/Z` | Масса, габариты | `content/cars/<car>/ui/ui_car.json` → `specs.weight/length/height/width` (`structures.py:218-225`) | **Нигде** в `AssettoCorsaEnv` — мёртвое поле, только логируется в `static_info` |
| `CAR_WHEELBASE`, `CAR_TRACK`, `CAR_WHEEL_R` | Колёсная база, колея, радиус шины | Живая телеметрия `ac.getCarState(TyreContactPoint/TyreRadius)` (`structures.py:200-211`) | **Нигде** в `AssettoCorsaEnv` — тоже мёртвое поле |
| `max_steer_rate` (900 град/с) | Лимит скорости поворота руля | `config.yml:73` — глобальный гиперпараметр, **не per-car**, ни разу не привязан к конкретной машине в коде | `ac_env.py:242,314` (`controls_rate_limit`) |
| Переключение передач | up/down по vJoy-кнопкам, без привязки к машине | `car_control.py:73-80` (`enable_gear_shift`/`shift_up`/`shift_down` → биты `onButtons`) — универсальный AC-байндинг "Gear Up/Down", работает одинаково для любой машины | `ac_client.py:255-273` |

### Как реально измерены `steer_map`/`brake_map` — найден методом обратного счёта

В README и коде явного описания метода нет, но в корне сабмодуля лежит
**готовый upstream-ноутбук `test_maps_creator.ipynb`** (не мной
написанный, уже был в репо) — он ровно это и делает:

- **brake_map** (`test_maps_creator.ipynb`, cell "Create the brake map"):
  на стоящей машине подаёт `brake` от −1 до 1 (21 точка), держит 25 шагов
  (1 c на 25 Гц), пишет фактический `state['brakeStatus']` из телеметрии,
  строит `BrakeMap` (кубическая интерполяция), сохраняет `brake_map.csv`.
- **steer_map** (та же тетрадь, cell "steer map"): подаёт `steer=±1`,
  читает `state['steerAngle']`, затем **бинарным поиском** (tolerance
  0.001) находит минимальную нормализованную команду руля, при которой
  достигается тот же максимальный угол — так и получаются "некруглые"
  0.5341796875 (dallara) / 0.7119140625 (bmw).

Доказательство, что это измерение, а не спецификация "на глаз": оба
значения — точные дроби от 16384 (`0.5341796875×16384 = 8752`,
`0.7119140625×16384 = 11664`), а `SCALE = 16384` — это константа шкалы
оси джойстика vJoy (`car_control.py:20`). Спецификацией такие числа не
получить, только чтением реальной позиции оси.

`brake_map.csv` у всех трёх машин **побайтово идентичен**. Живой замер для
RSR (4-я, совсем другая по классу машина — GTE вместо F3/GT3/родстера)
дал **точно такой же** набор чисел — это уже не совпадение на 2 случайных
числах, а 4 из 4 независимых замеров. Практический вывод: реакция педали
тормоза на команду в этой версии AC/этих машинах не моделируется
по-машинно, это общая для (как минимум) этих четырёх моделей кривая. Для
задачи это значит, что `brake_map.csv` для новой машины можно с высокой
уверенностью не перемерять, но я всё равно намеренно перемерил RSR вживую
(а не скопировал), чтобы это была не гипотеза, а проверенный факт.

`steer_map.csv` у `ks_mazda_miata` (`-1.0/1.0 → ±302.4`) на дроби от 16384
не раскладывается и заголовки колонок другие (`x_points,y_points` вместо
`action_steerAngle,steerAngle`) — похоже на более раннюю/другую методику
без бинарного поиска. Не найдено подтверждения, помечаю как «не
прояснено», не домысливаю.

### Проверка поддержки ручной коробки — подтверждено вживую

Код механизма переключения (`car_control.py:73-80`) car-agnostic — это
стандартный AC-байндинг "Gear Up"/"Gear Down" через vJoy-кнопки, никакой
car-specific конфиг под это не нужен. Официальное описание RSR
подтверждает секвентальную коробку (реальная машина без автомата, только
лепестки на руле).

Живая проверка (сессия Magione, RSR, ассист "Pro" в квик-меню AC):
`actualGear` до команды = 1, одна команда `shift_up` → 2, ещё через 1
секунду **без каких-либо команд** — всё ещё 2 (не откатилось и не
переключилось само). Значит: Auto Shifter реально выключен, переключение
идёт строго по нашим командам, автопереключения/дребезга нет. Ручная
коробка подтверждена не только по описанию машины, но и по факту работы.

## Живой тест — выполнен

Сессия: Magione, Porsche 911 RSR 2017, ассист-пресет "Pro" (Auto Shifter
выключен), 2026-09-21. Подключение через `client = assettoCorsa.make_client_only(...)`,
логика — точная копия `test_maps_creator.ipynb` (brake map sweep + steer
map endpoint/binary search), выполнена одноразовым скриптом (не сохранён
в репо — дублировал бы уже существующий notebook в сабмодуле, а по
правилу "форк только ради кода автора" ему там и не место; значения
перенесены в `racetune/ac_configs/cars/ks_porsche_911_rsr_2017/{brake,steer}_map.csv`).

Сессия проверена перед измерением: `client.simulation_management.get_static_info()["CarName"] == "ks_porsche_911_rsr_2017"`,
`TrackFullName == "magione"` — то есть точно та машина и та сессия, не
залипшее состояние от прошлой задачи.

## Побочная находка

`content/cars/ks_porsche_911_rsr_2017/ui/ui_car.json` — **невалидный
JSON**: `json.load` падает с `JSONDecodeError: Invalid control character
at: line 4 column 459` (сырой перенос строки внутри значения `description`,
не экранирован). Из-за этого `structures.py:216-227` (голый `except`)
молча не собирает `CAR_MASS`/`CAR_DIM_X/Y/Z` для этой машины — проверено
вживую: `static_info.get("CAR_MASS")` → `None`, хотя `specs.weight` в
файле есть. Функционально не критично (эти поля и так нигде не
используются в `AssettoCorsaEnv`, см. таблицу выше), но если когда-то
понадобятся — напрямую через `structures.py` они для RSR недоступны, файл
Kunos придётся чинить/обходить отдельно (не делал — вне задачи).

## Не сделано / открытые вопросы

- Почему `steer_map`/`brake_map` у RSR совпали с `dallara_f317` —
  для brake_map это теперь подтверждено на 4 независимых машинах (похоже
  на общую для AC кривую отклика педали, не баг). Для steer_map (240°,
  та же дробь) это только один случай совпадения из четырёх измеренных
  машин (bmw даёт другое значение, 320°) — может быть совпадением
  реальных лимитов поворота, а может быть общим шаблоном по классу
  машины; для окончательного вывода нужен ещё хотя бы один замер другой
  машины схожего класса. Не блокирует задачу.
- `ks_mazda_miata/steer_map.csv` использует другую методику/формат (без
  бинарного поиска, другие имена колонок) — не прояснено, для этой
  задачи не критично, оставляю как найденное расхождение.
- `ui_car.json` RSR невалиден как JSON (см. выше) — не чинил, вне задачи
  (это контент Kunos, не наш конфиг).
